# tnt-ce-etcd

etcd как источник конфигурации кластера для Tarantool Community Edition.
Узлу говорят, где лежит конфигурация, тем же разделом `config.etcd`, что
и в Enterprise; узел читает её по HTTP-шлюзу etcd API v3, сам замечает
правку, а при лежащем etcd поднимается на снимке последней прочитанной
и сам сходит с него, когда etcd вернётся.

```yaml
config:
  etcd: {endpoints: ['http://127.0.0.1:2379'], prefix: /demo}
```

```sh
tt cluster publish http://127.0.0.1:2379/demo cluster.yaml
TNT_CE_EXTENSIONS=tnt.ce.etcd tarantool --name instance-001 --config config.yaml
```

Зависит от `tnt-ce-extras` (точка входа ядра и открытие `config.etcd`
в схеме), `tnt-env` (путь снимка и выключатель отката), `tnt-context`
и `tnt-id` (своя область с новым `request_id` на каждый заход
наблюдения), `tnt-log`, `tnt-must`, `tnt-external` и `tnt-fs`
(атомарная подмена снимка со сбросом на диск).

## Зачем

Конфигурация, разложенная файлами по машинам, расходится, а общий
источник правды — etcd — Community Edition не принимает: раздел
`config.etcd` помечен «только Enterprise».

- **Раздел — по схеме ядра.** Те же имена и значения, что в Enterprise:
  конфигурация переезжает туда без правки.
- **Авария etcd не мешает перезапуску.** После каждого удачного чтения
  конфигурация ложится в локальный снимок, и узел, которому etcd
  не ответил, поднимается на нём с пометкой «устарела». Откат
  выключается, если расхождение опаснее простоя.
- **Правку узел замечает сам.** Раз в пять секунд наблюдатель спрашивает
  ревизию ключа и, если она выросла, просит ядро перечитать конфигурацию.
  Узел на снимке так же замечает вернувшийся etcd.
- **Прочитанное отличается от применённого.** Источник рассказывает ядру
  ревизию ключа, и ядро помнит отдельно прочитанную и применённую.
- **Перечитывание от узкой учётки.** Источник не трогает спейсов `box`.

Только для Community Edition.

## Установка

```sh
tt rocks install tnt-ce-etcd --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-ce-etcd.git
cd tnt-ce-etcd && tt rocks make --server=https://tnt-skein.github.io/rocks
```

## Как пользоваться

Модуль `tnt.ce.etcd` называют в `TNT_CE_EXTENSIONS` — в окружении
процесса или в `.env` каталога запуска. Конфигурацию кластера кладут
в ключ `<prefix>/config/all` (`tt cluster publish`), раздел `config.etcd`
пишут в файл узла:

| Поле | Что это |
|---|---|
| `endpoints`, `prefix` | адреса etcd по порядку и где лежит конфигурация; обязательны |
| `username`, `password` | вход; токен берётся на каждое чтение |
| `ssl.*` | `ca_file`, `ca_path`, `ssl_cert`, `ssl_key`, `verify_peer`, `verify_host` для `https://` |
| `http.request.*` | `timeout` (по умолчанию 5 с), `unix_socket`, `interface`, `verbose` |
| `watchers.*` | `reconnect_timeout` и `reconnect_max_attempts` наблюдения |

Снимок и откат настраиваются окружением, от рабочего каталога узла:

| Переменная | Что это | По умолчанию |
|---|---|---|
| `TNT_CE_ETCD_SNAPSHOT` | путь снимка | `var/etcd-config-snapshot.yaml` |
| `TNT_CE_ETCD_FALLBACK` | разрешён ли откат на снимок (`off` выключает) | разрешён |

Что источник говорит о себе, видно через каркас:

```lua
require('tnt.ce.extras').status().sources.etcd
--> { ready = true, stale = false, watching = true, revision = 3,
-->   endpoint = 'http://127.0.0.1:2379', synced_at = 1790216786.48 }
```

Модули доступны и по отдельности: `tnt.ce.etcd.client` — чтение ключа
с перебором адресов и входом, `tnt.ce.etcd.snapshot` — снимок,
`tnt.ce.etcd.source` — сам источник.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Ни etcd, ни сеть проверкам не нужны: транспорт и клиент — двойники,
снимок уходит во временный каталог, отказы диска — подмена `fio`
у `tnt-fs`, окружение — подмена `tnt-env`. Две живые проверки поднимают
настоящий узел 3.8: с рабочим каталогом, отличным от каталога запуска,
и на снимке, с которого узел сам сходит, когда на адресе etcd
заговаривает двойник его HTTP-шлюза. Покрытие строк — 100 %, убитых
мутантов — 100 % (150 проверок, 262 мутанта в пяти модулях).
